# Agent 循环（turn / step）

## 一句话

把"用户说一句话"变成"多次模型调用 + 工具执行"的状态机，并在明确的条件下停下来。

## 为什么需要

模型本身无状态，一次调用只能"说"，不能"做"。要改代码，必须：

```
说（调用工具） → 做（执行工具） → 看结果 → 再说 → … → 收尾
```

这段编排就是 harness 的核心。没有它，模型只是一次性的文本生成器。

## turn 与 step

- **turn（轮）**：一次用户输入，到最终答复为止。
- **step（步）**：一轮中的一次模型请求，以及它请求的工具执行。

```
turn 开始
├─ step 1: 请求模型 → 返回 2 个工具调用 → 执行 → 回填结果
├─ step 2: 请求模型 → 返回 1 个工具调用 → 执行 → 回填结果
└─ step 3: 请求模型 → 不再调用工具 → 输出最终答复 → turn 结束
```

## 终止条件（必须都有）

1. 模型不再请求工具（正常完成）；
2. 达到 `maxStepsPerTurn`；
3. 单轮超时；
4. 用户取消；
5. 不可恢复的错误（provider 认证失败等）。

缺任何一个，都可能出现"停不下来的 agent"。

## 带着这些问题读

1. 工具执行失败时，turn 应该继续还是结束？由谁决定？
2. 用户在工具执行中按 Ctrl+C，取消信号应该传到哪几层？
3. 为什么循环不能持有"唯一真相"？
4. 同一轮里两个工具并行执行，结果顺序如何保证？

## 常见误解

- **"循环 = while (true) 调模型"**：没有预算与终止条件的循环，是烧 token 的机器。
- **"工具错了就抛异常结束"**：错误应该作为数据回给模型，让它有机会纠正。
- **"循环负责所有状态"**：循环只做决策，事实必须落事件；否则崩溃后无法恢复。
