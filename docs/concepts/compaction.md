# 压缩（compaction）

## 一句话

当对话快撑满上下文窗口时，把**较早的一段历史替换成摘要**，而不是删掉它。

## 为什么不能直接删

- 删掉会破坏"重放 == 实时"：日志里还在，投影里没了，两份状态开始漂移；
- 删掉可能丢掉关键约束（用户的任务目标、已确认的决策）；
- 删掉会让前缀变化方式不可预测，缓存与调试都变难。

正确做法：追加一条 `compaction/committed` 事件，声明"用摘要替换 [from, to) 区间"。
原始事件保留，投影时应用替换规则。

## 什么时候触发

1. 估算 token ≥ `contextWindow × triggerRatio`（默认 0.75）；
2. provider 返回 context overflow（先压缩，再重试一次）；
3. 用户手动 `/compact`。

估算要用"字符启发式 + 最近一次 usage 校准"，不能只靠字符数：中英文差异很大。

## 压缩做什么

1. 保留 system prompt、最近 `keepRecentTurns` 轮、当前 step；
2. 对更早的区域生成摘要，固定小节：
   Primary Request / Key Decisions / Files & Code / Errors & Fixes /
   Pending / Next Step / Critical Context；
3. 摘要失败的退化路径：确定性摘要（文件清单 + 最近错误 + 最后 N 条消息），
   保证主循环不被阻塞；
4. 提交为事件，替换点之前的字节保持不变（KV cache 友好）。

## 和"工具输出裁剪"的关系

两件不同的事：

- **压缩**：处理"历史太长"，用摘要替换整段；
- **裁剪**：处理"单条结果太大"，把旧的大输出替换成头尾 + spill 路径。

裁剪可以在压缩之前独立发生；两者都服务于同一个 token 预算。

## 常见误解

- **"压缩就是总结一下"**：它是有事务边界、可重放的状态变更。
- **"摘要越短越好"**：丢掉了约束，模型会重复犯错；摘要要保"决策与待办"。
- **"压缩只在快满时发生"**：手动 `/compact` 与 overflow 恢复也是入口。
